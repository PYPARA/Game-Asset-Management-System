# 供应商发送、Fake-IP 与生成恢复

## 网络策略

用户配置的 HTTPS 供应商域名解析到 `198.18.0.0/15` 时自动兼容，诊断值为 `fake_ip_compatible`。这不是可信代理认证。其他禁止地址仍拒绝；混合解析中包含禁止地址也拒绝。字面 IP 不获得此例外。原域名、TLS 校验、系统代理环境、禁止自动重定向保持不变。

模型发现、JSON 请求、参考图 multipart 请求共用请求入口；DNS 检查在线程中运行并以 5 秒应用层超时隔离事件循环。连接测试不触发生成计数。规划运行仍使用已有隔离的供应商运行目录，不修改个人 Codex 设置。

## 发送与预算

Attempt 初始 `not_sent`，本地参数、凭据、参考文件、DNS 和 HTTP 请求构造通过后，事务检查租约、取消状态和本请求调用上限，然后写入 `dispatch_started`，增加调用次数及费用估算。收到完整 HTTP 响应后写入 `response_received`。旧记录迁移为 `legacy_unknown`，不推断交付。

同一结构化文字 Attempt 内可能发生格式回退或 JSON 修复；每次 HTTP 发送分别增加 `dispatch_count` 并记录事件，受同一请求调用上限约束。`billable` 是发送计数兼容字段，不代表供应商已确认收费。供应商没有价格时费用估算未知。

发送后超时、断线、进程退出保留交付未知，不自动重试。本地准备失败不消耗调用额度，需明确恢复；恢复复用请求哈希和幂等键。服务端接收 `RemediationCreate.idempotency_key`，重复提交同一操作返回已有动作，不产生新生成。不同内容复用键返回 409。

## 历史数据修正

```sh
uv run --project apps/api gams run reconcile-local-failures PLAN_ID --json
```

命令只修正指定批次内符合旧版 DNS 守卫精确错误、失败分类与配对发送/失败事件证据的 Attempt；排除已有供应商请求 ID、产物及结果版本的记录。事务撤销误计，写入 `provider.accounting_corrected`，重复执行不再修改。不会重排任务，不会改变已确认模型、提示词、参考或供应商快照。
