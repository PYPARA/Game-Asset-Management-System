# 生成工作区与持久规划

生成中心的地址是 `/generation` 和 `/generation/:sessionId`。桌面会话列表 232px，工作面板默认 400px，可调整、折叠；小于 1200px 收起工作面板，小于 900px 使用面板切换。项目保持炭灰主题、Phosphor 图标。原 820px 侧栏约定已替换。

## 执行边界

- `PlanningTurn` 保存逻辑用户回合；`PlanningAttempt` 保存执行尝试、租约、心跳、终止错误；`PlanningCommand` 是 API 到 worker 的持久交互命令。
- `serve` 在 uvicorn reload 子进程之外监督独立 worker。API 重启不停止 worker。worker 崩溃后监督进程重启它，新 worker 独占状态目录锁、接管过期租约。
- 独立部署可设置 `GAME_ASSETS_MANAGE_PLANNING_WORKER=false`，并单独运行 `game-assets-api planning-worker`。直接嵌入 `create_app` 的测试默认使用原进程内 runner；生产 CLI 默认 `GAME_ASSETS_PLANNING_EXTERNAL_WORKER=true`。
- 同一状态目录只运行一个规划 worker。当前为本机 SQLite 工作台，并非多主机分布式队列。
- 初始尝试与消息在同一事务写入。恢复创建新 attempt，关联原 turn，不创建 user.message。最多三次自动恢复；用户停止的规划不会自动恢复。等待回答时保留问题，worker 重启后回答通过新底层执行继续。
- 首先恢复原远端线程；明确的线程丢失或 `paginated_threads` 不兼容才新建线程。重建输入包含全部已回答问题、最近对话、当前人工草案、完整历史文件和以前批次的资产/修订。
- 草案编辑有 base_hash 校验。Agent 运行期间人工修改导致哈希变化，Agent 提案单独保留，由用户比较后保留或应用。

## 确认与结果

`ConversationBatch` 将一个会话关联到多个不可变 GenerationPlan，保存确认时草案版本。旧 `plan_id` 回填第一批，继续作为最近批次兼容投影。确认按草案哈希幂等，SQLite 确认事务串行读取，重复确认返回原批次。下一条指令开启下一版草案，原批次继续执行。

规划恢复会调用所选文字供应商进行规划，但不会确认或执行资产生成。检查并生成的最终确认继续调用既有 Controller、Runner、预算、供应商冻结、QA 流程。结果面板展示批次、任务进度、图片证据、候选版本及 QA；失败处理使用现有运行检查器，批准与发布仍在资产库。

## 前端连续性

共享事件投影在页面外保存，离开页面可断开订阅，回来从已应用游标补齐。历史接口逐页读取，实时与历史按事件 ID 去重，游标不回退；较旧快照不能覆盖更新状态。流式文本约 50ms 聚合刷新，时间线按 60 项窗口浏览，资产选择结果显示上限并支持搜索，避免渲染全部历史和全部资产。

输入草稿和发送操作键按会话保存在 sessionStorage。失败保留原文及幂等键。IME 候选确认不发送。仅在接近底部时自动跟随；阅读历史显示新消息入口。已回答问题以摘要显示。预览操作与选择引用独立，图片/文档/音频/关联媒体共用版本预览器。

## 验证与限制

回归测试：恢复保留文官/中性立绘/自动设计且无重复消息；协议不兼容回退；API 队列关闭不取消任务；worker 取消并重启后租约接管；同会话两个独立批次及旧确认重放；一万条逆序重复 delta 聚合；600 条迟到历史不回退游标。测试只使用假适配器和假供应商。另有连续连接失败最多三次自动恢复、恢复不创建生成计划、IME、千级资产搜索、预览 Escape 焦点返回测试。

实际浏览器检查包括真实旧会话、已回答摘要、协议错误解释、图片参考预览，以及 1440/1280/1024/390 宽度。旧版本已经错误写入的重复用户消息保留作为历史审计，不会伪造清理历史。

仍需上线环境持续观察 SDK 本身的停滞。应用层无事件超时提供恢复保护；心跳代表 worker 存活，不代表模型必然有进展。恢复能力 `can_resume` 在未实际尝试前为未知，不能以连接正常推断恢复一定成功。未对真实供应商执行付费验收，也未进行人工读屏完整验收。


## 后续验收边界

目前历史 API 仍返回原始事件分页，客户端聚合后按固定窗口浏览；尚未提供服务端聚合消息分页或可变高度滚动虚拟列表。全局入口目前显示需要关注会话总数，尚未拆成运行中、待回答、未读结果三个独立计数。方案冲突提供两份草案比较和明确选择，尚未做到逐字段差异高亮。完整读屏测试、音频真实文件播放及真实 SDK 长时间运行的故障注入仍需专门验收。这些不能用单元测试通过替代。

## 2026-09-22 路由与卡顿修复

- 规划使用会话 `route_defaults.text`（缺省继承系统文字路由），不使用个人 Codex 默认模型或登录。`agent_model` 为旧兼容字段，不再决定供应商规划路由。
- App Server 使用应用状态目录下独立的 `planning-codex/<provider-hash>`；供应商明确配置为 Responses API。未配置、未解锁或不兼容时失败并保留现场，绝不回退个人账号。API 重启会清空内存凭据，需要在供应商渠道重新解锁。
- 独立 worker 通过权限为 0600 的本机 Unix socket 获取内存凭据；凭据只进入专用 App Server 环境，不写数据库、启动参数、对话或工作目录。执行工具的环境使用 `shell_environment_policy.inherit=none`。
- 流式事件带 assistant item ID；commentary 完成不再隐藏后续 final stream。草案 JSON 流显示接收进度，完成后才应用经过校验的方案。旧无 item ID 的混合流也不直接展示 JSON。
- 原始片段仍写 SQLite，但不再每个片段重写全部审计镜像；非片段事件及终止时写完整镜像。持续排空 stderr、扩大 JSONL 完成帧容量，避免管道堵塞和长方案帧读取失败。
- 桌面工作区仅两行布局，移动导航出现时才有第三行；参考结果网格使用内容高度及卡片最小高度，千级资产不会压成横线。
- 本次没有重新执行真实付费生成。供应商 Responses API 的实际返回能力仍需解锁后端到端确认；配置验证与模拟进程回归不能替代真实供应商验收。

修复验证：后端规划/路由相关 48 项通过，新增管道与超时用例使专项测试共 6 项通过；前端全量 91 项通过，最终流式投影 4 项复测通过。真实 App Server 隔离探针只执行 thread/start（未开始模型回合），返回模型 gpt-5.6-sol、提供方 gams。

## 2026-09-22 引用校验与思考等级

真实失败方案把固定文档修订的 `input_hash` 当成引用 `sha256`。现在仅对显式固定修订、无 rendition 的文档，将与该修订 input_hash 完全一致的值转换为 content_hash；未知哈希与错误修订仍拒绝。提示明确区分两者，保留旧上下文哈希结构以免升级使会话失效。模型 candidate_path 不再参与落地决策，候选目录由系统分配；会话路由设置由用户保存值决定。拒绝的提案保留在 result 中，便于诊断而无需盲目重跑。

已回答卡支持查看/收起。文字路由可选择 reasoning_effort；规划通过 model_reasoning_effort 配置发给 App Server，文字产物通过任务 metadata 冻结并传入 chat/completions 的 reasoning_effort。模型不支持的等级由供应商明确拒绝，不静默降级。真实失败方案经校正已通过普通与确认前校验，保存回原会话，未创建生成批次。

本轮验证：后端规划、恢复、供应商及生成相关 60 项通过；前端全量 93 项通过，后续回答卡/思考等级专项 19 项复测通过；构建通过。真实会话 a3b8498b-8190-4d23-a1fd-695afada720a 的失败方案已修正并保存为草案第 4 版，普通校验和确认前校验通过，未调用确认接口。批次历史回归关闭模拟后台生产，避免测试自身在第二次确认前异步改变上下文。

## 2026-09-22 编辑与确认流程修复

生成中心不再显示全局近期任务底栏，工作区占满顶栏下方空间，结果面板保留运行进度。普通草案编辑使用会话已有上下文快照；不因全项目目录/供应商信息漂移阻止模型、思考等级、透明度编辑。base_hash 并发校验以及实时引用、路径、模型校验仍保留。最终确认继续检查项目快照；刷新后保留编辑并要求用户重新核对，不自动二次确认。

确认预览内提供每项警告的勾选，与右栏共享接受状态；禁用原因和提交错误在弹窗内显示。修复行内错误的操作按钮被通用关闭按钮样式压成竖排的问题。回归覆盖无关资产新增后连续修改思考等级/透明度、预览中完成全部警告确认、上下文刷新后不自动执行。测试仅使用模拟生成。
